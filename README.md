---------------------------------------猜数字-------------------------------
endl和\n的区别。endl和cerr都可以直接刷新缓存区。endl自带\n和刷新缓存区的2项功能。
这个例子展示endl和\n的区别：
int main() {
    cout << "第一步：准备读取数据...\n";  // 使用了 \n，进了缓冲区，但没刷新
    
    // 这里发生了一个严重的错误（比如除以 0，或者操作了非法的内存）
    int a = 10 / 0; 
    
    cout << "第二步：读取完毕！\n";
    return 0;
}
当你的程序跑起来时，实际上是这样的分工合作： 

第 1 步： CPU（工人）在车间里读到了 cout << "第一步...\n"; 这行代码。CPU 的动作是：把这串文字打包，扔到“装卸货站台”（输出缓冲区）里，等待发车。

第 2 步： 扔完包裹后，CPU 根本不关心车发了没有，它立刻转身去执行下一条代码：计算 10 / 0。

第 3 步： CPU 在车间里一算，发现数学上根本不能除以 0！这触发了操作系统的最高级别警报，系统直接“强行炸毁”了你的整个工厂（程序崩溃，进程被强制杀死）。

结局： 既然工厂都被强制拆除了，那个还停在装卸货站台上、没来得及发往屏幕的包裹（缓冲区里的文字），自然也就跟着灰飞烟灭了。


在 C++ 中，这辆“输出快递车”通常只有在以下 4 种情况下才会发车（刷新缓冲区）：

1.车满了（容量溢出）： 就像你刚才猜想的那样。

2.强制命令（手动刷新）： 你使用了 endl 或 std::flush。

3.遇到需要键盘输入时： 当代码执行到 cin >> b; 时，C++ 会非常聪明地先把 cout 快递车里的东西发走，以防你要问用户的提示语（比如 "请猜数字："）还没印出来，程序就傻乎乎地在那等输入。

4.正常下班（程序安全结束）： 当程序顺利执行到 return 0; 时，系统会把所有没发走的车全部清理发走。


---------------------------------转换数据------------------------------------------
1. 软件工程架构思维
解耦（分离业务与表现层）： 绝不能把纯计算逻辑（如公式）和界面交互（如 cin/cout）混在同一个函数里。剥离出来的纯函数才能在终端、网页、App 中无限复用。

消灭“魔法数字”： 代码中直接出现的常数（如 1.8、32.0）必须用有名字的 constexpr 常量代替，让代码自带说明书。

2. 现代 C++ 的安全与性能利器
constexpr 的双重身份：

修饰变量：强制在编译时算好，算不出就报错。一个 constexpr 变量一定是 const，但一个 const 变量不一定是 constexpr。

修饰函数：薛定谔的计算——传入常量时，在编译期瞬间算出（0耗时）；传入用户输入时，自动降级为普通运行时函数。

传参的黄金标准 const std::string&： 传复杂对象时，加上 &（引用）直接传递原地址，省去极耗性能的拷贝；加上 const 上锁，防止函数内部篡改数据。

3. 极致压缩的表达式思维
直接 Return 表达式： return 后面不仅能跟变量，更能直接跟“算术公式”甚至“比较逻辑”。例如 return (a * 2); 或 return age >= 18;，直接免去“赚差价”的临时变量。

if 内部的变量声明（防御性编程）： 写成 if (int a = getNumber())，让变量 a 出生在判断时，并在大括号结束后立刻灰飞烟灭，绝不污染外部环境。

4. 终极输入防崩模板（防御 cin 罢工）
cin >> value 返回的是读取状态。一旦读到错误类型，cin 就会红灯罢工（状态变为 False）。

抢救三步曲：

cin.clear();：按灭红灯，消除报错状态。

cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');：开启抽水机，把堵在通道里的垃圾字符连同回车键一起全部抽干。

提示用户并 continue 重新循环。

5. 告别 C 语言的坏习惯
警惕 using namespace std; 炸弹： 在全局使用它会把标准库的几千个名字倒进你的代码里，极易引发命名冲突（如自定义的 count 与 std::count 冲突）。工业代码一律显式写 std::。

卫语句（Guard Clauses）消灭 else： 只要 if 大括号里有 return、break 或 continue，就绝对不要写 else。尽早退出，让代码保持扁平化。

最小作用域原则： 变量尽量定义在离使用它最近的地方（哪怕是 while 循环内部），现代编译器会自动优化，绝对不会拖慢运行速度。

6. 排错与代码整洁之道
幽灵空格与格式化： 从网页复制的代码常带入编译器不认识的特殊空格（导致莫名其妙的报错）。手动敲击 Tab 或 Space，或者依赖 IDE 的“一键格式化（如 Shift+Alt+F）”来保持代码和注释对齐。

括号匹配检查： 漏掉函数末尾的 } 会导致编译器误以为你在进行“函数嵌套定义”。
